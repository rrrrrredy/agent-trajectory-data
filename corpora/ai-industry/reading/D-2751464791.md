别让龙虾把事做歪：OpenClaw 的误触发、越权、漂移与 Skill 设计

### 一、误触发、越权、漂移

很多人以为，OpenClaw 把事做歪，应该是那种一眼就看得出来的错误：答非所问、明显胡说、格式混乱、逻辑断裂。可在真实工作里，更麻烦的反而不是这种“显错”，而是另一种：它看起来八九不离十，甚至比很多人手工写出来还顺，但细看会发现，最关键的那一层已经偏掉了。**这种“偏而不显”的问题，比“错得离谱”更危险。**因为前者很容易直接流入后续流程，最后以一种非常正式、非常体面的方式，把错误放大。

可以把这类问题分成三种：误触发、越权、漂移。

**误触发的意思很简单：这个 Skill 根本不该在这个时机被调起来。**比如你只是想让系统帮你整理一下最近两周某个方向的公开信息，方便自己先过一遍材料。正常情况下，它应该先做信息归类、去重、按主题挂接，最多再补一版调研摘要。但如果路由太宽，它很可能直接把任务理解成“写一篇研究简报”，进一步又滑向“给出几条趋势判断”，甚至顺手附上“对我们战略的三点启发”。问题是，你明明还没走到那一步。你要的是收材料，它却直接替你进了判断层。很多知识工作就是这样被做歪的：不是不会写，而是写早了。

**越权比误触发更进一步。**误触发至少还是调错了 Skill，越权则是 Skill 已经被调起来了，但它做了本不该由它做的事。一个很典型的例子，是战略规划材料整理。  
你把几份讨论纪要、几页手写想法、几段聊天记录交给系统，原意只是想把这些零散内容整理成一版“目标、抓手、风险、待决策项”的讨论底稿，好让下次会议更高效。这时候，一个边界清楚的 Skill 应该做的是归纳、去重、分层、标注冲突。但一个边界模糊的 Skill 很容易越权：它会开始替你判断哪条路径更重要、哪块资源更应该倾斜、哪些讨论应该被收口成统一方向。这已经不是整理，而是代替管理判断了。越权最可怕的地方在于，它常常披着“主动性”的外衣。看起来像是系统更懂事了、更有想法了、更能往前推进工作了。但从组织视角看，这恰恰是最需要收住的地方。因为一旦系统把整理、建议、裁决混成同一层，责任边界就彻底模糊了。

**漂移不是一下子越权，而是慢慢偏。**最开始它可能还是忠实的，后来随着输出变长、材料变杂、结论层级升高，它开始不自觉地把“事实”加工成“判断”，再把“判断”加工成“结论”。研究报告合稿里尤其容易出现这种事。一开始，系统还在认真合并几份材料里的观点。可一旦发现几份文档里有相近信号，它就可能把这些“重复出现的现象”上升为“已经形成的趋势”；再往后，它会把个别作者的判断写成“普遍共识”；最后甚至把资料里没有明确支持的话，写成一种很像成熟分析的表达。表面看，文章更顺了，实际上，证据和结论已经脱钩了。漂移并不总是因为模型“爱幻想”，很多时候只是因为系统没有被要求持续回指证据，也没有被要求在不确定时停下来。它一路写顺了，于是就一路漂远了。

这三类问题，在工作场景里都特别常见：信息调研最怕误触发，你只想收材料，它却先帮你得出结论；战略讨论最怕越权，你只是想整理讨论，它却替你做收口；研究合稿最怕漂移，你只是想整合已有观点，它却开始偷偷“优化”成一种并不存在的统一判断。那怎么防？

**第一，路由要收紧。**不要写那种“负责行业研究与战略分析”的大 Skill。越大越空，越空越容易误触发。最好明确：这是信息整理、调研摘要、趋势观察，还是战略建议。层级不一样，权限就不一样。

**第二，输出要分层。**尤其不要把“事实摘要、观察判断、行动建议”揉在一起。哪怕放在同一篇文稿里，也要明确分段、分标签、分责任。这样至少你知道哪里是事实，哪里是解释，哪里是建议。

**第三，权限要后置。**默认先让它整理、归纳、列问题，而不是直接让它替你做结论。对高风险层级，宁可先停下来，让人来确认。

**第四，证据要回指。**尤其是做研究和规划时，任何稍微强一点的判断，都应该能回到材料里找到支撑。如果找不到，就应该显式写成“推测”或“待验证”，而不是写成像事实一样的句子。

**第五，异常要允许停机。**材料不够，停；信息冲突，停；任务意图不清，先停在较低层级。很多漂移，都是因为系统被默认要求“无论如何都要写点什么”。

说到底，OpenClaw 真正危险的地方，不是它不会做，而是它做错的时候依然显得很会做。这也是为什么我越来越觉得，一个靠谱的 Agent 系统，第一原则不是“多做一点”，而是“少做错一点”。

**name**: 月度 AI 行业分析  
**version:** v1  
**category**: research

**description**: >  
将指定月度窗口内的 AI 行业相关材料进行整理、去重、归类和初步分析，输出适合内部阅读的月度分析稿。该 Skill 重点解决“信息收拢、结构化整理、主题归类、有限度观察提炼”的问题，不直接替代正式战略规划、投资判断、业务决策或对外发布口径。

**when_to_use**:

- 用户明确要“月报 / 月度分析 / 月度简报 / 月度回顾”
- 用户希望基于一个月内的多来源 AI 行业材料生成分析稿
- 用户需要给研究团队、负责人或管理层准备月度观察材料
- 用户需要为后续深度报告或战略讨论准备月度底稿
- 用户请求“整理 + 归类 + 初步观察”，而不是单点事实查询

**when_not_to_use**:

- 只查单一公司、单一产品、单一模型或单一事件
- 只做链接清单、新闻汇总、原始资料收集
- 只要提纲、邮件、一页摘要等轻量输出
- 需要季度、年度或跨周期专题研究
- 需要明确的战略建议、资源配置建议、投资判断、业务决策
- 材料明显不足，无法支撑月度分析层级输出

**routing_notes**:

- 该 Skill 只处理“月度分析”层级，不默认升级为“战略建议”
- 若用户意图不清，默认按“L2 研究分析版”执行
- 若用户只要事实整理，应路由到更轻量的信息整理或调研摘要 Skill
- 若用户请求高风险结论，应停在分析输入层，不继续上升

**required_inputs**:

- time_range: 月度时间范围
- analysis_scope: 分析范围（全球 / 国内 / 海外 / 某专题）
- source_scope: 信息来源范围
- audience: 目标读者
- output_level: L1 / L2 / L3

**optional_inputs**:

- geography_split: 是否区分国内外
- topic_dimensions: 是否按固定主题分栏
- focus_entities: 是否重点关注某些公司/产品/方向
- output_format: markdown / brief / table / ppt_text
- include_sources: 是否保留证据来源
- include_followups: 是否输出“待跟进问题”
