# Agent 运行轨迹与可执行环境 v0.4

本版把历史数据整理、实际排错过程、可执行修复题和业务状态环境放在一个独立包里。v0.3 在 prior/ 中逐字节保留，里面继续包含 v0.2 和 v0.1。当前新增任务以开发诊断和环境验证为用途。

## 内容

| 内容 | 数量与边界 |
|---|---|
| 历史报告评审输入 | 45 份；保留 221 份评审记录，不是 221 次独立调用 |
| 历史研究执行 | 原有 4 次研究运行；134 份原生返回可读，其中 28 份带截断标记 |
| 真实处理问题链 | 9 条：原始失败、观察定位、修改、重试与验证证据 |
| 可执行 Python 排错题 | 7 题，每题包含初始错误、修复不完整、参考修复与私有测试 |
| 研究交接环境 | 10 个场景，来自两组研究材料，各有 5 种状态条件 |
| 四类要素覆盖目录 | 98 个历史/新增任务、案例版本或运行条目，明确重叠与缺失 |

七个排错题涵盖 JSONL Unicode 分隔、客户端附注、历史哈希字段、冻结输入格式、失败尝试保留、敏感模式误报，以及保存加载后的观察顺序。它们是与实际记录关联的最小复现；attempt-retention 从已有失败记录派生，没有声称曾发生过“删除失败”的原始程序错误。

业务场景包括正常交接、未登记来源、两次限流后恢复、来源权限撤销、任务单版本冲突。它们具有可变状态和提交评分；组织背景与事件明确为合成，不代表来自真实企业的内部系统。

## 目录与使用

    prior/                          未修改的历史数据
    tasks/<id>/instruction.md       任务目标与约束
    tasks/<id>/environment/         初始程序或业务状态
    tasks/<id>/tests/               私有验证器
    tasks/<id>/solution/            参考解法
    executions/<id>/                实际控制执行、结果和操作轨迹
    processing/events.jsonl        选定真实工具调用与返回
    processing/incidents.jsonl     问题定位、修改、重试、验收关系
    processing/source.json         原会话截取边界、源摘要和排除规则
    coverage.jsonl                 四类要素及缺失情况
    environments/                  实际运行版本及历史环境限制
    rubrics/                       历史记录可评分的范围
    verify_dataset.py              独立验证、learner 导出和打包入口

仓库根目录验证：

    py -3 -X utf8 -B scripts/runtime_dataset.py verify data/agent-runtime-v0.4

解压后验证：

    py -3 -X utf8 -B verify_dataset.py verify .

导出排错任务给模型：

    py -3 -X utf8 -B verify_dataset.py export-learner . --task jsonl-unicode --output D:\Codex\_tmp\learner-jsonl
    py -3 -X utf8 -B tasks/jsonl-unicode/tests/verify.py D:\Codex\_tmp\learner-jsonl

导出只含题面和初始程序，不含参考解法或隐藏测试。评分器默认退出码 0 表示通过，1 表示失败，并输出具体检查结果。不要让模型直接读取包含解法的完整归档。

业务环境的交互和评分命令见 [RL 环境说明](RL-ENVIRONMENT.zh-CN.md)。JSONL 接口可以直接接收外部 Agent 的动作；指定独立输出路径后保存实际交互。调用者未提供模型身份时明确标 external_client。

## 原始排错记录

原会话截取到第 3059 行，保存选定时间窗口中的可见记录和每个原始行的 SHA256。隐藏推理、系统消息、全局指令、被删除的商城实现不在采集范围内。原始命令作为数据文本保存，不执行历史命令。

问题链的诊断摘要是依据可见证据整理的事后解释，不能当成模型隐含思维。六条早期问题包括 JSONL 检查失败、误报、附注差异、旧哈希字段、额外配置和正式评审输入位置。另三条来自本轮：源事件行号指错、保存加载后的观察不一致、测试保存时意外消除了错误条件。

后来的修复没有覆盖早期失败。比如附注问题修正后，下一次构建仍因哈希字段缺失而失败；数据明确保留这种“解决了一个问题，但任务还没完成”的状态。

## 评价边界

历史模型意见和已有裁定均保留身份及版本关系，不自动成为质量真值。四次历史研究运行缺少完整外部网页状态；某些作者轨迹没有被保存，无法恢复的部分继续标缺失。coverage.jsonl 是覆盖清单，98 行不是 98 个独立可训练任务。

本机实际运行 CPython 3.11.3 与标准库。未安装 Docker，因此只声称本地执行验证。排错子进程不是执行不可信程序的安全沙箱；业务环境只有限定的数据动作，不提供宿主命令执行。

现有全部材料都已被开发过程使用，held-out=0。本轮新增付费模型调用、训练记录和训练完成模型均为 0。参考脚本通过只证明环境可解及当前检查有效，不证明模型能力或跨企业泛化。

验证结果、最终包哈希与私有发布入口以 [验收记录](ACCEPTANCE.zh-CN.md)为准。
