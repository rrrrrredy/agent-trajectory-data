# v0.14 候选：自行构造有效回归输入

登记日期：2026-09-29。候选筛查已通过；本文件记录采集前的题目设计与原型验证，不代表实际模型已完成任务。

## 要增加的能力

本任务要求模型自己构造合法输入并给出正确预期，用它复现错误，修改代码后以完全相同的回归输入复测。现有修复任务只开放固定公例，不能记录这类主动检验。租户作用域与幂等语义和既有工作区任务有联系，本批不宣称首次覆盖这些业务规则。

本批只登记一个原创合成家族。题目输入、初态、参考解法、错误反例与期望结果均为新编，不来自旧报告、生产故障或第三方程序。正式材料为 [scoped-event-regression.json](../configs/runtime-v0.14/scoped-event-regression.json)。

## 输入、结果和两个可区分的原因

输入为 events 列表，最多 32 条；每条恰有 tenant_id、event_id、payload 三个字符串字段，长度均不超过 80。两个 ID 非空，可含分隔符和 Unicode，按原始字符串严格比较；payload 可以为空。基本形状和长度由输入域保证，不要求修复任意畸形 JSON。

返回首次出现的完整事件列表，顺序与输入一致。身份键是 tenant_id 与 event_id 的有序组合。同键、同 payload 的后续事件作为重放忽略；同键、不同 payload 必须对整个输入抛出 ValueError。不同键不能因相同 event_id、相同 payload 或拼接后相同而合并。

| 实现与问题 | 区分它的输入 | 正确行为 |
|---|---|---|
| 初态只按 event_id 去重 | 两个租户使用同一 event_id | 保留两个事件 |
| 部分修复改为组合键，但忽略冲突 | 同一租户同一 event_id 出现不同 payload | 抛 ValueError |
| 用冒号拼接两字段 | (a:b,c) 与 (a,b:c) | 保留两个事件 |
| 冲突采用最后一次写入 | 同一组合键的 payload 改变 | 抛 ValueError |

跨租户同 ID 的回归输入可区分初态与部分修复；同键变 payload 的输入可区分部分修复与正确解法。单个复杂输入可能同时触发多个错误，不能据此声称已证明模型区分了所有错误原因；实际采集后应依据它提交的具体检验与观察报告能力范围。

## 原型验证证据

公例为“空列表”和“普通相同内容重放”，初态均能通过。10 个私例覆盖跨租户同 ID、同键内容冲突、交错重放、分隔符碰撞、大小写区别、首次出现顺序、空及 Unicode 内容、重复重放、同内容不同键、靠后出现的冲突。所有期望均手写固定，没有由候选代码自动产生。

| 实现 | 2 个公例 | 10 个私例 |
|---|---|---|
| 初态：event_id 键 | 通过 | 失败 |
| 部分修复：组合键但不报冲突 | 通过 | 失败 |
| 分隔符拼接键 | 通过 | 失败 |
| 最后一次写入 | 通过 | 失败 |
| 正确参考：元组键字典 | 通过 | 通过 |
| 独立 oracle 原型：逐项扫描已接受事件 | 通过 | 通过 |

原型通过现有 repair_executor 实际执行。参考与 oracle 使用不同算法，并共同核对手写期望。六种实现都通过两个公例，只有正确参考与 oracle 通过全部 10 个私例。此处的 12 个用例属于一个任务，不是 12 个独立任务，也不是模型表现。

旧 research-repair-1 环境的 test 不接受自建 cases，实际返回 422 / no_arguments。把正确参考作为修复完整执行后，所有私例通过，但整体 reward 为 0；唯一失败评分项是 baseline_failure_observed，因为固定公例在初态就通过。这证明不能通过更换任务文案表达新增能力，需要允许自建检验的最小环境支持。

## 最小环境改动与边界

新增环境须在运行自建检验前检查输入域，并独立核对模型提交的预期；错误预期或畸形输入不能制造可计分的“已复现失败”。检验回执应绑定输入、预期、当前代码和版本；评分须确认模型在初态观察过有效失败，并在最终代码对同一检验完成成功复测。最终结果仍由固定私例独立检查。公开样例不得包含 reference_probe、参考代码或私例。

正式材料只提供 oracle_id=scoped-event-dedup-v1，不含 oracle 源码；oracle 由评价侧独立实现。reference_probe 是脚本参考使用的跨租户同 ID 输入，不能注入模型上下文或计成模型自建检验。
