## 可以直接做什么

从仓库根目录验证、导出一份输入，以及导出一条运行的实际观察：

    py -3 -B scripts/research_corpus.py verify data/research-corpus-v0.3
    py -3 -B scripts/research_corpus.py export-input data/research-corpus-v0.3 --case dev-U01 --output artifacts/U01-input.json
    py -3 -B scripts/research_corpus.py export-input data/research-corpus-v0.3 --case formal-F01 --output artifacts/F01-input.json
    py -3 -B scripts/research_corpus.py observe data/research-corpus-v0.3 --run run-03 --output artifacts/run-03-observations.jsonl

export-input 仅导出冻结的 system/user，不加载评审分数和后续裁定到输入中。observe 导出已有消息、调用与返回，归档中的命令保持为数据，不执行。两个导出入口均拒绝覆盖已有文件。

解压数据包后，直接使用包内 verify_dataset.py 执行相同的 verify、export-input、observe 命令即可。只需 Python 标准库，不依赖仓库中的服务或运行中的应用。

从原始选定材料重建到新目录：

    py -3 -B scripts/research_corpus.py build --source D:\Codex\industry-research-framework-field-eval\optimization-20260907 --sessions D:\Codex\_home\sessions\2026\09\07 --prior data/research-history-v0.2 --output data/research-corpus-rebuild

sessions 参数只定位已在 v0.2 绑定的四个会话ID，不批量导入该目录的其他会话。

## 数据之间怎样对应

| 文件 | 保存的内容 |
|---|---|
| tasks.jsonl | 任务、来源分组、条件、报告摘要和输入位置 |
| inputs/*.json | 精确的冻结送评输入 |
| reviews.jsonl | 原模型判断、报告与输入绑定状态、原索引是否选用 |
| author_attempts.jsonl | 原作者尝试、原错误、后续补跑及其关系 |
| source_adjudications.jsonl | 原有来源裁定，标作继承记录而非本次重新核验的真值 |
| native_calls.jsonl | 执行器请求与返回配对、可读性和截断标记 |
| sources/native/*.jsonl | 实际可见消息、调用代码和工具返回文本 |
| sources/objects/ | 按内容摘要保存的报告、来源包、冻结材料与原评审 |
| source_index.json | 原始来源、哈希、当前选择索引和原生记录删减说明 |
| prior/ | 完整保留的 v0.2，含旧版任务与来源材料 |

原生会话与 v0.2 的会话ID、8轮任务提示和最终消息已经绑定。六份最终消息的客户端记忆引用脚注被记录后移除，报告正文保持一致。隐藏推理、系统提示、用户环境配置和压缩摘要不入包。

开发题的相关关系沿用原清单并作传递合并，P03 与原 CAL-02 视频研究继续共享家族。历史对照研究的两种条件及补跑仍属于同一题族。这些分组只反映已记录关系，不证明不同组相互独立。

## 失败和判断的使用边界

本版新增保留的12次原始作者未完成，来源是额度错误。它们是实际运行失败，可用于研究停止和补跑记录；不能据此判定模型不会完成该研究题。22份可送评报告不意味着22次原始作者尝试全部成功。

评审的可解析、输入绑定正确与报告质量是不同属性。当前选中的180个槽位都能绑定相应冻结输入和报告；评审结论仍是模型判断。原有来源裁定保留证据与理由，gold_label 不作升级，quality_outcome 保持 not_assessed。

本版已经恢复当时实际返回给模型的文本，因此不再只有网页动作元数据。但工具返回中有摘要和截断，外部网页状态、未返回内容及交互环境仍不完整，不能声称可重新执行整个互联网研究环境。

45份新增任务是报告评审输入。它们扩大主题覆盖，不冒充45条完整作者轨迹。四个原生会话补观察与原运行共用身份，不重复计入运行数。登记表故障任务和语义案例均为真实独立任务，保留于 prior/；构造情境是其来源材料的性质。

所有新增材料都已被历史研究、评审或本次构建接触，固定为 development。未见测试任务、训练导出和新增模型调用均为0；没有新增访谈、标注或人工审核环节。
