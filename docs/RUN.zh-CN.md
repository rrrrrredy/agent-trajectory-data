# 自动批次运行与数据位置

当前运行命令与结果见 [v0.6 数据说明](DATASET-v0.6.zh-CN.md)。当前构建范围见[构建计划](PLAN.zh-CN.md)，已有本地入口见[运行说明](SYSTEM.zh-CN.md)。本文保留有限模型批次的原始运行说明。

本文记录模型适配器与 v0.2 有限批次。新增结构化事实入口、独立评测包与月调用上限见[交付说明](DELIVERY.zh-CN.md)，数据现状见[当前判断](CONCLUSION.zh-CN.md)。
目前已经能用一个命令完成：生成任务 → 实际执行模型或脚本 → 保存轨迹和失败 → 程序验收 → 按用途导出。每个样本都由程序处理，无法验证时隔离，没有人工标注、人工复核或人工异常队列。

## 运行真实模型批次

需要 Python 3.10 以上，以及已有有效登录的 Codex CLI。当前配置请求 gpt-6-astra。模型和预算写在 configs/codex-local.json；凭据保留在 Codex 自己的登录存储中。

在仓库目录运行：

```powershell
py -3 -B -m agentdata --root data/model-v0.2 pipeline --config configs/codex-local.json --batch-id model-001
```

没有 Windows Python launcher 的环境可将 py -3 换成 python。当前实测平台为 Windows；不把自动化单元测试等同于所有操作系统的实测。

默认生成一个母题的三个变体：正常证据、404 缺失证据、429 后恢复。每次调用让模型给出下一步 JSON 动作，宿主执行模拟工具后，把真实返回结果交给下一次调用。参考答案不会放入模型的任务输入。

批次预算为最多 8 次适配器调用，每个任务最多 90 秒，整批最多 600 秒。调用次数在发送请求前写入持久状态；即使进程中断也不返还这个次数。CLI 内部可能自行重试传输，所以这个数不是底层 HTTP 请求总数。CLI 不提供账单金额，此处没有金额预算，也不会把费用记成零。

## 中断、重启和失败

再次执行同一命令、同一 batch-id，会恢复已有状态。完成的任务跳过；调用是否取消无法确认的中断任务标记为 interrupted，不再次发送同一请求。剩余任务仅在原有截止时间和调用预算内继续。

同一批次的配置冻结，修改后需要使用新的 batch-id。每个批次只能有一个活动 worker，操作系统会在进程退出后释放锁。预算耗尽或截止时间到达，程序停止当前批次并保留尚未执行的任务状态。

配置错误直接停止；运行中的单个任务异常保留部分目录与失败记录，后续任务仍受总预算控制。来源缺失、答案错误、运行中断、元数据不完整和无法判定的质量问题分别保存，不改写为成功。

重复启动测试已确认：首批 7 次模型调用完成后，再运行相同命令，调用计数仍为 7，调用文件数量也仍为 7。

任务文件不可覆盖。版本升级改变生成元数据时，使用新的数据根目录保留旧版本，避免改写历史任务。

## 数据在哪里

```text
data/model-v0.2/
  tasks/                         冻结任务、环境与私有参考答案
  runs/<run-id>/
    task_snapshot.json           本次执行使用的任务快照
    events.jsonl                 宿主可见动作、工具观察和终态
    run.json                     运行、评分、用量和来源摘要
    model_calls/0001/
      request.json               宿主提供给 CLI 的任务输入
      events.jsonl               CLI 发出的可见事件，排除推理事件
      capture.json               会话、用量、请求配置和关联哈希
      stderr.txt                 过滤后的诊断输出
  batches/<batch-id>/
    config.json                  本批冻结配置
    state.json                   预算预约、任务状态和恢复依据
    summary.json                 批次结果及导出数量
    diagnostic.json              内部诊断包
    sft.json                     训练用途门禁的输出及隔离原因
```

诊断导出会内嵌调用输入、可见事件和采集摘要，读取导出包不需要回到原机器取这些文件。原始快照仍然保持私有。

## 怎样理解“真实”

task_origin=synthetic 表示题目是合成的；actor_kind=model_cli 表示通过模型客户端实际调用；execution_mode=closed_world_observed 表示工具环境是受控模拟环境。它们不是实际客户任务，也不是开放互联网环境。

模型身份分两栏保存：model_requested 是请求的配置，model_reported 是接口明确返回的版本。当前 CLI 没有提供后者，因此保持 null。会话 ID、可见输出和用量是实际观察值；本地哈希不能证明拥有文件写权限的人从未修改过记录。

request.json 保存本程序发送的任务输入，不包含 CLI 自己的完整系统上下文。隐藏推理事件不进入数据包。已知输入、缓存输入和输出 token 分别统计，缓存输入属于输入 token 的子集。

## 为什么训练包可以为空

当前自带配置的模型输出仅用于内部诊断，所以真实首批诊断包有 3 条记录，训练包有 0 条。程序会报告原因，不会为了增加训练数据数量而放松用途限制。

训练导出要求任务和模型输出都允许该用途、判定成功、来源与实际动作一致、用量完整，并且不属于隐藏测试家族。脚本控制数据默认排除。用途策略是机器可执行配置，不能替代来源本身的权限依据。

## 当前首批结果

3 个合成任务，7 次实际 CLI 模型调用，3 条轨迹通过确定性验收。正常读取事实、404 后弃答、429 后恢复三条路径均已执行。输入 token 合计 76,725，其中缓存输入 8,320；输出 token 合计 444。账单金额未知。

正式批次之前有 1 次接入探测，模型已返回动作，但采集器将 CLI 启动提示判为协议错误。该原始失败单独保留，没有覆盖或混入正式批次的成功统计。其可见事件记录了 10,880 输入 token 和 58 输出 token。

这里的 3/3 是同一小型合成任务家族的控制结果，不代表开放式研究能力、训练收益或商业价值已经得到验证。
