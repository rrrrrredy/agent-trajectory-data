# 当前数据判断与下一步

当前应继续建设数据内容，停止平台扩展。项目定位是独立闭源的 Agent 执行轨迹与评测数据集。运行环境和脚本只承担采集、执行、验证与导出的必要工作。

原要求包括真实数据、合成数据、评测、决策与失败记录，以及个人自动运行。之后明确要求新建闭源仓库、取消访谈与人工环节。最新要求将盈利放到数据集构建并跑通之后，并要求清理商城、支付和相关技能。实施范围以[收缩后的构建计划](PLAN.zh-CN.md)为准。

## 已验证的事实

- 当前目录有 300 条合成任务、300 条脚本控制轨迹、2 条实际模型轨迹。脚本与模型均已重新通过诊断质量检查。
- 旧协议另有 3 条实际模型轨迹，已重新通过质量检查。两批共 5 条，任务均为合成任务。
- 已导入的一份真实会话含 319 条可见事件，156 个工具调用与 155 个工具结果；它不是完整可重放的研究任务。
- 真实 SFT 和偏好对导出均为 0；未放宽用途限制来增加数量。
- 私有评测 ZIP 含 260 条非 holdout 任务，原文件哈希保持不变。
- 删除商城改动后，原有 82 项工程测试全部通过。

## 仍然没有完成的部分

现有数据没有充分连接 research-toolkit 的原始研究任务、材料、主张、产物与同一次运行的完整轨迹。已有模板题覆盖有限，实际模型失败不足，合成变体还没有围绕已对齐的真实研究片段形成血缘。

因此，不能把“自动生成 300 条题”和“82 项测试通过”写成用户所要求的数据集已经完成。5 条模型运行证明接口与受控环境可用，不能证明真实研究任务覆盖或训练效果。

## 下一项具体工作

先把明确选定的真实运行与研究产物归一化，逐条判断能否构成有输入、动作、结果和判定依据的样本。保留缺失与 unknown，再跑通一个可自动核验的任务片段；由它派生少量有意义的合成变体，最后冻结数据版本和评测切分。

已有服务、额度、轮询和交付管理退出当前主流程。商城支付实现与附带数据已删除；不继续开发网站，也不引入人工生产环节。
