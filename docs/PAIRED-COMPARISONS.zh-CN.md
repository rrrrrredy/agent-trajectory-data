# 同一个任务加示范，究竟省了什么？

完整示范在已有用途实验的 16 组同题对照中全部增加了输入 token，只有 5 组减少了环境动作。格式实验的单个 JSON 示例虽然降低了总输入量，却有一半对照增加输入量。选择上下文示范时，应同时看格式拒绝、实际动作和最终结果，不能只看总回合或平均 token。

这里重新分析既有归档，没有新增模型调用。按同一轮、同一供应商、同一任务配对；每格只有一次执行，16 对仍来自 4 个开发任务，不是 16 个独立任务或重复试验。[任务与完整案例](tasks/README.md) · [原实验口径与下载](START-HERE.zh-CN.md#已有研究给出的明确取舍)。

## 完整示范：少的主要是格式拒绝

A 为基础说明，C 为完整示范。下表的“减少／相同／增加”均是 C 相对 A；总差值为 C − A。

| 指标 | 减少的对照 | 相同 | 增加的对照 | 总差值 |
| --- | ---: | ---: | ---: | ---: |
| 最终 reward | 0 | 16 | 0 | 0 |
| 模型回合 | 12 | 3 | 1 | −42 |
| 格式拒绝 | 11 | 4 | 1 | −41 |
| 环境动作 | 5 | 8 | 3 | −1 |
| 上报输入 token | 0 | 0 | 16 | +1,761,731 |

合计的环境动作只少 1，是不同对照增减相抵后的结果，不是每题都少做一点。三个增加环境动作的对照和五个减少的对照全部保留在[逐对数值](analysis/paired-A-C.json)中。

| 供应商（每个 4 对） | 回合总差 | 格式拒绝总差 | 环境动作总差 | C/A 输入 token 总量比 |
| --- | ---: | ---: | ---: | ---: |
| deepseek | −13 | −15 | +2 | 3.59× |
| glm | −3 | −4 | +1 | 3.74× |
| kimi | −1 | 0 | −1 | 3.90× |
| longcat | −25 | −22 | −3 | 2.97× |

在这个样本里，deepseek 和 glm 的回合减少伴随着环境动作增加。kimi 原本就没有格式拒绝，长示范仅少 1 个环境动作，却增加到约 3.90 倍输入 token。该观察不支持把长示范默认放进全部任务；也不能据此判定长示范在未见任务上无效。reward 全部相同存在明显天花板，无法证明业务能力提升。

## 一个 JSON 示例：总量改善不代表每题改善

N/E 是另一轮修复接口后的对照，E 增加一个 JSON 格式示例。下表为 E 相对 N，不与 A/C 跨轮比较。

| 指标 | 减少的对照 | 相同 | 增加的对照 | 总差值 |
| --- | ---: | ---: | ---: | ---: |
| 最终 reward | 0 | 15 | 1 | +1 |
| 模型回合 | 7 | 3 | 6 | −22 |
| 格式拒绝 | 7 | 3 | 6 | −12 |
| 环境动作 | 7 | 4 | 5 | −10 |
| 上报输入 token | 8 | 0 | 8 | −93,360 |

[逐对数值](analysis/paired-N-E.json)保留正负差值及两边交付状态。唯一 reward 不同的是 `longcat/cedar-pilot`：N 为 0，E 为 1；但 E 有 32 回合、15 次格式拒绝、113,107 个输入 token，均高于 N 的 28 回合、8 次格式拒绝、78,996 个输入 token。内容结果更好与格式效率更差可以同时发生；一格一次不能说明格式示例导致了成功，也不能把该次内容修复算作格式错误减少。

输入 token 是供应商上报量。表内按相同供应商比较，但仍未换算缓存、输入输出单价、计费失败请求或人工时间；所有供应商相加仅是记录量，不能解释为统一货币成本。reward=1 也可能表示正确阻塞，具体含义需看任务和交付状态。

## 自己按任务复算

沿用已经发布的两份 ZIP，不下载新数据，不调用模型。在仓库根目录运行：

```sh
python -X utf8 examples/read_study.py ../usefulness/data/usefulness-study-20260929 --compare A C --output paired-A-C.json
python -X utf8 examples/read_study.py ../format/data/format-study-20260929 --compare N E --output paired-N-E.json
python -X utf8 examples/read_study.py ../format/data/format-study-20260929 --compare N E --task cedar-pilot --provider longcat
```

输出包含两边指标、右减左的差值、原 run 路径、交付状态、失败项和 `results.json` 的 SHA-256。不会把缺少一边的任务静默排除；重复条件或未完成执行会报错。输出文件须不存在。配对只控制归档中记录的供应商和任务，不额外声称底层服务版本、随机性或调用时间已经控制。

实际取舍是先在自己的目标任务上检查接口与上下文开销，再决定是否保留示范。现有结果足以说明总平均数的局限；要区分随机波动与稳定收益，还需要固定接口下的同题重复及来源不同的未见任务。本轮没有为扩样而重复调用，也没有把诊断记录改成训练数据。
