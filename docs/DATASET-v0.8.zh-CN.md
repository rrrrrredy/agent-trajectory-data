# v0.8：可验证的研究动作与首次模型轨迹

本轮新增 6 个合成来源家族、24 个可执行场景，覆盖证据时点选择、指标与单位计算、评审发现到实际修订验证。冻结输入和评分后，6 个选定任务全部在首次模型执行中完成，共 52 次调用，分别用 9、7、7、9、10、10 步；没有因每条上限截断。

新增素材明确标为合成；模型动作、工具返回、失败和提交来自实际执行。旧真实报告与历史运行继续保存在原版本，新包通过上一发布标签和 SHA-256 关联它们。新包没有把合成公司背景写成真实企业记录。

## 本轮修复了什么

旧版说明校验只检查非空文字、证据回执与写入顺序，无法充分约束文字里的结论。旧判定保留。v3 改用明确的结构化结果、范围、限制和逐行引用，并由宿主生成最终说明；传入的自由文本若与该说明不一致会被拒绝。提交时还必须满足真实文档末态、读取时机和任务单版本要求。

这能验证合成事实、计算、引用和状态。它没有解决开放式报告的自由文本事实判断；不能将此次改动称作通用研究质量评分。

两个关键反例是：没有实际修改却声称评审已解决，以及写完说明后才读取支持材料。两者都会失败。403 对应的有证据 blocked 结论继续得到正向评分。受支持的评审意见要求真正修改；与来源冲突的意见必须拒绝。

采集器在调用前预留原全局额度，保存请求和返回，再执行动作并保存检查点。崩溃测试证实，已经捕获的结果会本地重放；未知在途调用被隔离，不会重复发送。每个请求显示真实剩余步数、调用次数与时间。

## 直接运行

解压公开发布包后验证全部内容：

    py -3 -X utf8 -B runtime_release.py verify .

对实际评审修订轨迹评分：

    py -3 -X utf8 -B task-entrypoints/orchid-quota-counterfactual-v3/tests/verify.py model/episodes/orchid-quota-counterfactual-v3/episode.json

执行参考解法，输出写在包外：

    py -3 -X utf8 -B task-entrypoints/orchid-quota-counterfactual-v3/solution/reference.py ../reference-v8.json

启动新的环境交互：

    py -3 -X utf8 -B research_env_v3.py batch/tasks/orchid-quota-counterfactual-v3/scenario.json --output ../episode-v8.json

环境先输出初态，然后每行接收一个 JSON 动作：

    {"tool":"read","args":{"document_id":"policy"}}

ResearchEnv.reset(seed) 返回公开初态和 info；step(action) 返回 observation、reward、terminated、truncated、info。非终局奖励为 0；满足所有任务约束的提交奖励为 1。环境有 24 步硬上限，当前运行仅需 Python 标准库。完整交付包含评价侧材料，实际策略只能接收宿主给出的公开观察，不能直接读取整包。

## 如何理解 6 条成功

模型配置为 gpt-6-astra，身份按实际调用记录中的请求参数报告。6 条均为新建独立上下文的首次执行；开发者已见题，三种任务机制在 train/test 之间共享。这是既有真实独立开发任务上的成功结果；开发者已见题的情况如实记录，本次未估计跨公司能力或 toolkit 效果。

本轮评价具有明确答案的证据操作，下一轮应优先增加长依赖、真实可复现的新失败和更难的不可判定边界。不能仅通过改名、增加 seed 或重复运行提升“独立任务”数量。配置和扩充入口见 [批次构建说明](BUILDING-BATCHES.zh-CN.md)。

公开 toolkit 只接收通用 JSONL 修复与回归，提交为 `28524448eaf6534125a24dd1ea26e986016c8aea`。本轮数据、场景、评分及过程证据交付于公开数据集仓库。
