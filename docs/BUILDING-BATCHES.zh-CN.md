# 扩充数据批次

当前实现用 Python 标准库、JSON 配置和不可变输出目录。扩充已有三类任务不需要新增服务。新批次先离线验证，再用冻结的任务、模型配置和有界预算采集实际动作。

## 配置与输入

参考 `configs/runtime-v0.8/batch.json`。每个来源项声明 family_id、train/test、mechanism、material 和 variants；批次声明 as_of、max_steps、评分范围、上游 toolkit 提交及上一发布版本。

material 是单独的 JSON 文件，保存合成来源行、待核对主张、上下文、来源身份与用途。评审任务另带发现列表。新增来源必须有新素材；同一素材及所有变体归入同一 family_id。当前自动适配器只接受明确标注的合成材料，历史真实报告仍使用原有导入器，不能通过改标签进入此适配器。

| 机制 | 需要的材料 | 可验证结果 |
|---|---|---|
| evidence_update | 带生效日期和修订号的指标记录、待检查主张 | 选择适用时点的记录，说明主张是否一致 |
| numeric_consistency | 指标、期间、数量、单位、主张 | 对同期间同指标做单位换算与求和 |
| review_revision | 来源事实、错误主张、评审发现 | 实际修改主张、拒绝错误建议，并重新读取验证 |

现有工具故障是两次 429、永久 403 和一次任务单 409。反事实由机制转换器生成，必须与 clean 基线产生不同的正确结论；同一来源的多个故障不计为新的来源家族。新增机制需要实现明确的状态转移和独立可算的评分，并补正反例。

## 离线构建

在仓库根目录执行，输出目录必须尚不存在：

    py -3 -X utf8 -B scripts/runtime_batch.py build configs/<新批次>/batch.json data/<新批次>
    py -3 -X utf8 -B scripts/runtime_batch.py verify data/<新批次>

构建器冻结输入，生成每题场景、通过公开观察执行的参考轨迹、五种错误交付对照及来源分离的脚本示范。脚本示范标为 scripted_reference，不计作模型轨迹。序列化后的场景要重新加载并逐步回放，不能只验证内存对象。

交付脚本另为每题生成 tests/verify.py、solution/reference.py 和 environment.json。独立验收会运行这些入口，核对控制样本，并测试重算外围哈希后的语义篡改。

## 实际采集与续跑

collection.json 单独固定 task_ids、model、max_new_calls、monthly_model_calls、max_call_seconds、max_batch_seconds 及本批授权记录。旧批次剩余额度不自动转给下一批。

每次模型请求只含任务公开观察、工具返回与真实剩余预算。场景中的评价侧答案、参考解法、评分检查和完整内部状态不进入请求。当前实际提供方使用独立 Codex CLI 上下文，模型身份记录为请求配置；没有服务端独立身份回执时不补造模型版本。

已冻结且已授权的批次入口是：

    py -3 -X utf8 -u -B scripts/runtime_collect.py execute data/<任务批次> data/<模型批次> --config configs/<新批次>/collection.json --ledger data/production-current

调用前在原全局账本预留额度；原记录保留。每次请求、可见回复、动作和状态检查点当次落盘。重新运行相同命令会核对输入冻结，重放已有完整返回；发现已启动却没有完整返回的调用，会保存为 unknown_inflight_call_quarantined，禁止盲目重发。恢复不会重置截止时间或步数。

首次执行、恢复执行、预算截断、提供方故障和未知调用分别记录。失败仍有价值，但错误动作与外部截断不能混为同一种负样本。当前训练导出只接纳成功的 train 家族，保留该轨迹中的工具失败与恢复动作；test 家族即使成功也排除。

## 每批看什么

重点查看新增来源家族、任务机制、有效反事实、正反例表现、完整回放比例、实际首次完成数、各停止原因、模型轨迹与决策导出数量、token 用量、实际额度和来源重叠。费用没有提供方回执时记为空值。

持续增长依靠新素材和新的困难边界。改名、重复运行、单纯增加 seed 或故障组合只能增加记录，不能直接增加独立性。当前 test 家族与 train 家族不重合，但共用任务机制，而且开发者已看过素材；这不是外部盲测。

当前环境支持 reset/step 与终局奖励，能够直接供策略执行和评价。它模拟文档、任务单、权限、重试和修改验证；没有模拟完整企业组织、开放网络或长期业务结果。时效题中的未来生效记录是预置干扰项，不代表已经实现材料按真实时间流入。
