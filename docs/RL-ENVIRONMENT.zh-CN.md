# 从研究记录到可执行的 Agent 环境

交付单位是任务、可观察轨迹、可运行环境、结果、评分依据与参考解法。v0.6 用四组来源构建 20 个研究交接场景：两组新虚构来源用于训练，两组真实归档用于评测。组织背景、任务单和故障事件均明确标为合成；真实来源不等于真实企业运行记录。

## 环境契约

| 部分 | 当前实现 |
|---|---|
| 目标 | 检查来源登记，记录证据与限制，更新任务单并提交 |
| 初态 | 冻结的任务单、来源表、主张表、规则、交接记录和历史版本 |
| 角色与权限 | 证据分析员通过工具读取有权访问、当时已存在的文档 |
| 工具 | search、read、read_ticket、write_note、update_ticket、submit |
| 状态 | 观察、读取回执、说明文档、任务单状态与版本、请求次数 |
| 故障 | 临时 429、权限拒绝、版本冲突、缺失来源链接 |
| 评价 | 当前可见材料、证据读取顺序、交付范围、说明和任务单末态 |
| 终止 | submit 结束；环境 30 步耗尽时截断；外部采集预算另行记录 |
| 参考解法 | 只通过公开工具完成任务；不要求唯一动作顺序 |
| 记录 | 每一步动作、观察、状态前后摘要、奖励与终止标记；模型记录另含实际请求与可见回复 |

BusinessEnv.reset(seed) 返回初始观察与任务身份；step(action) 返回 observation、reward、terminated、truncated、info。实现只依赖 Python 标准库。更换 seed 不会自动形成独立来源或独立任务。

## 评分依据

非终止步骤 reward=0。提交后六项都满足才得 1：

1. ready、needs_revision 或 blocked 与当前可访问登记表一致。
2. 范围是 registry_integrity_only，来源登记检查不能被写成事实验证。
3. 必要材料有当前版本成功读取回执；真实 403/404 能证明阻塞，429 只能证明一次临时失败。
4. 任务单状态与版本和提交一致，并发冲突必须被处理。
5. 更新前已有说明；证据在写说明时已经取得，后续补读不能追溯支持旧说明。
6. 临时来源读取不超过三次，即最多重试两次。

说明文本验证存在及证据关联，不自动评价其写作质量。证据参数 evidence_ids 接受文档编号，例如 ["policy","handoff","sources","claims"]。读取回执 read-3 是宿主内部的证据记录，不是此参数所需的文档编号。

评分入口逐步重放动作，比对观察和最终状态。未提交的实际运行返回 incomplete_episode；此时没有终局业务判定。原失败会保留，修正后的动作构成新的事件或新版本。

## 运行入口

在 v0.6 独立解压目录：

    py -3 -X utf8 -B verify_runtime.py verify .
    py -3 -X utf8 -B curriculum/business_env_v2.py curriculum/tasks/business-synthetic-capacity-tool_retry-v2/environment/scenario.json --output ../episode-v6.json

第二条命令输出初始观察后接受逐行 JSON，例如：

    {"tool":"search","args":{"query":""}}
    {"tool":"read","args":{"document_id":"policy"}}

参考解法与评分：

    py -3 -X utf8 -B curriculum/tasks/business-synthetic-capacity-tool_retry-v2/solution/reference.py --output ../reference-v6.json
    py -3 -X utf8 -B curriculum/tasks/business-synthetic-capacity-tool_retry-v2/tests/verify.py ../reference-v6.json

运行文件写到包外，已有路径不会被覆盖。无效输入、执行中重置、提前结束及失败均有记录。完整包含评价侧资料，策略只能接收公开观察；让模型读取整包会破坏评测条件。

## 采集过程与环境过程分别记录

本批采集上限是每条 12 次决策，而环境上限是 30 步。实际请求未显示较小的外部上限，三条模型首次尝试都被采集器提前停止，不能由 reward=0 推出其完整任务终局能力。execution-evidence/execution-limits.json 和每条 stop_reason 保存了这种区别。

新的客户端应把实际调用上限与剩余额度明确提供给策略。本版原始模型请求维持冻结；来源分离、参考可解和重放通过不改变这三条未完成的事实。成功模型示范导出为 0，合成示范与偏好对分别标记。

## 从材料生成环境

冻结原始材料及来源摘要 → 确定任务发生时可见的信息 → 建立角色、权限、目标和初态 → 生成可观察工具与状态转移 → 建立可检验的末态要求 → 执行参考与负对照 → 保存真实尝试及筛选依据。

原始资料、事后解释、机器提取与合成补充使用不同标签。缺失内容继续标缺失；未来结果放在评价侧，不提前放进题面。适配器只能把有确定性依据的部分变成评分真值，其他事实维持未评定。

同源报告、修订和全部派生故障场景一起切分。当前训练与评测来源不重合，但共享模板；可迁移的候选能力是查证、权限与时间判断、有限重试、冲突恢复和证据不足时给出有限结论，其跨组织效果尚无充分证据。

旧 v0.4 另外保留七个 Python 排错任务及完整研究历史。其执行器运行可信候选程序，进程隔离不等于操作系统安全沙箱。环境结构、具体样本和适用边界见 [v0.6 数据说明](DATASET-v0.6.zh-CN.md)。
