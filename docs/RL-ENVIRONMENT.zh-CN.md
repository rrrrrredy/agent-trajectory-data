# v0.10：可执行的真实故障复现

research-repair-1 将三条历史真实问题链整理为 9 个有边界的 Python 函数修复任务。每题提供任务契约、公开例子、初始错误代码、独立隐藏测试、参考解法和评分入口；完整历史证据仅供评价端追溯。布局与并发扰动分别标为合成。原机器和完整仓库不在此环境中。

动作包括 read、patch、test、read_ticket、write_note、update_ticket、submit。patch 要求唯一匹配的旧文本和当前版本；409 后必须读取新版本再重试。test 执行当前候选函数并返回绑定代码摘要、版本和测试编号的回执。公开 tests 是诊断工具，终局还检查隐藏行为。

模型必须先复现初态失败，再实际修改、复读、复测、写有证据的说明并提交任务单。评分器重放全部动作，核对代码、测试和说明的时序。测试之后再改代码、跳过初始失败、引用旧测试，或通过公开测试但漏掉隐藏约束，均不能得分。每步返回 reward/terminated/truncated；中间奖励为 0，全部终局条件满足为 1，30 步耗尽为截断。

候选程序仅使用文档声明的纯函数 Python 子集。它适用于这批小型复现，不能作为通用不可信代码隔离设施。诊断文本留存，但自由文本解释质量不在自动评分的保证范围。六条模型执行全部成功，仍继承原始诊断来源用途。

环境材料、参考和评分在评价侧；实际策略请求只有公开观察和历史动作。模型失败、外部预算截断、工具恢复与最终验证分别导出。跨版本记录利用已知来源关系避免切分冲突；详细结果见 [v0.10 数据说明](DATASET-v0.10.zh-CN.md)。以下保留前版环境接口和边界。

# v0.9：依赖、冲突与分项修订

ResearchEnv v4 新增三种机制、6 个合成来源家族和 24 个可执行场景。初始观察只给入口文档，模型需沿公开 references 找到所需材料。未来材料按固定 as_of 隐藏；搜索和直接读取都不泄露其正文。

任务可以合理地结束为 ready、needs_revision 或 blocked。证据等级相同时存在冲突，应明确保留不确定性；时间更新不能擅自覆盖权威规则。多项修订任务必须验证评审依据，实际修好 C1/C2，保留 C0，并在每次修改后复读最新版本。一次 409 不会被删除或转换成成功动作。

reset(seed) 返回公开观察和环境信息；step(action) 返回 observation、reward、terminated、truncated、info。每步奖励单独保存在事件中：中间步骤为 0，提交且全部约束满足为 1；32 步耗尽是截断。稀疏奖励不等于中间动作没有价值，逐步观察和失败回执保留在完整轨迹中。可以由外部策略直接驱动接口，无需连接企业系统。

评分有九项约束：终止、结构化结果、正确值、范围、实际任务修复、证据链接、文本与结构一致、任务单末态、有限重试。引用必须在写说明时已有相应版本和正文摘要的读取回执；后补读取不能支持旧说明。环境记录 reward 和状态摘要，评分器重新执行动作核对，不信任客户端自报奖励。

参考解法、完整场景与测试脚本交付给评价端，策略只接收宿主公开观察。仅把整个 ZIP 放入模型上下文会泄露评价侧资料。CLI 输出、实际采集请求、可见动作说明及训练筛选均可以追溯；不保留隐藏推理。

v4 是有边界的文档与任务单模拟，尚未涵盖完整企业权限体系、长周期后果和开放式写作质量。真实历史报告与新合成场景分别保留来源标签；不能把合成组织背景称为真实企业运行记录。具体结果见 [v0.9 数据说明](DATASET-v0.9.zh-CN.md)与[批次构建流程](BUILDING-BATCHES.zh-CN.md)。

以下保留旧环境说明及原有边界。

# v0.8 的可执行研究环境

当前新增环境为 ResearchEnv v3，覆盖证据适用日期、期间与单位核算、评审修订三个机制。24 个场景来自 6 个合成来源家族；六条实际模型首次执行均完成。每题提供 environment.json、tests/verify.py 和 solution/reference.py，主包可以独立解压执行。

reset/step 接口返回公开观察、奖励、终止与截断标志。环境在文档、读取回执、主张修改、结构化说明和版本化任务单之间推进；24 步耗尽记为截断。工具新增 revise_claim，成功修改后必须重新读取，评分才承认已验证的修复。对永久拒绝访问，应交付有证据的 blocked。

说明使用结构化结论与引用，再生成文本。评分同时约束结果、范围、限制、行级引用、说明创建时已有的证据、实际修改与任务单末态。自由文本报告质量不在 v3 评分范围。模型只能看到宿主公开观察，完整包中的评分和参考文件应留在评价侧。

运行命令及结果见 [v0.8 数据说明](DATASET-v0.8.zh-CN.md)，新增批次见 [构建流程](BUILDING-BATCHES.zh-CN.md)。以下保留旧 v0.7 环境说明，其规则与评分没有被改写。

# 从研究记录到可执行的 Agent 环境

交付单位是任务、可观察轨迹、可运行环境、结果、评分依据与参考解法。v0.7 原样包含 v0.6 用四组来源构建的 20 个研究交接场景：两组新虚构来源用于训练，两组真实归档用于评测。组织背景、任务单和故障事件均明确标为合成；真实来源不等于真实企业运行记录。

## 环境契约

| 部分 | 当前实现 |
|---|---|
| 目标 | 检查来源登记，记录证据与限制，更新任务单并提交 |
| 初态 | 冻结的任务单、来源表、主张表、规则、交接记录和历史版本 |
| 角色与权限 | 证据分析员通过工具读取有权访问、当时已存在的文档 |
| 工具 | search、read、read_ticket、write_note、update_ticket、submit |
| 状态 | 观察、读取回执、说明文档、任务单状态与版本、请求次数 |
| 故障 | 临时 429、权限拒绝、版本冲突、缺失来源链接 |
| 评价 | 当前可见材料、证据读取顺序、交付范围、说明和任务单末态 |
| 终止 | submit 结束；环境 30 步耗尽时截断；外部采集预算另行记录 |
| 参考解法 | 只通过公开工具完成任务；不要求唯一动作顺序 |
| 记录 | 每一步动作、观察、状态前后摘要、奖励与终止标记；模型记录另含实际请求与可见回复 |

BusinessEnv.reset(seed) 返回初始观察与任务身份；step(action) 返回 observation、reward、terminated、truncated、info。实现只依赖 Python 标准库。更换 seed 不会自动形成独立来源或独立任务。

## 评分依据

非终止步骤 reward=0。提交后六项都满足才得 1：

1. ready、needs_revision 或 blocked 与当前可访问登记表一致。
2. 范围是 registry_integrity_only，来源登记检查不能被写成事实验证。
3. 必要材料有当前版本成功读取回执；真实 403/404 能证明阻塞，429 只能证明一次临时失败。
4. 任务单状态与版本和提交一致，并发冲突必须被处理。
5. 更新前已有说明；证据在写说明时已经取得，后续补读不能追溯支持旧说明。
6. 临时来源读取不超过三次，即最多重试两次。

说明文本验证存在及证据关联，不自动评价其写作质量。证据参数 evidence_ids 接受文档编号，例如 ["policy","handoff","sources","claims"]。读取回执 read-3 是宿主内部的证据记录，不是此参数所需的文档编号。

评分入口逐步重放动作，比对观察和最终状态。未提交的实际运行返回 incomplete_episode；此时没有终局业务判定。原失败会保留，修正后的动作构成新的事件或新版本。

## 运行入口

在 v0.7 独立解压目录：

    py -3 -X utf8 -B verify_recovery.py verify .
    py -3 -X utf8 -B prior/curriculum/business_env_v2.py prior/curriculum/tasks/business-synthetic-capacity-tool_retry-v2/environment/scenario.json --output ../episode-v7.json

第二条命令输出初始观察后接受逐行 JSON，例如：

    {"tool":"search","args":{"query":""}}
    {"tool":"read","args":{"document_id":"policy"}}

参考解法与评分：

    py -3 -X utf8 -B prior/curriculum/tasks/business-synthetic-capacity-tool_retry-v2/solution/reference.py --output ../reference-v7.json
    py -3 -X utf8 -B prior/curriculum/tasks/business-synthetic-capacity-tool_retry-v2/tests/verify.py ../reference-v7.json

运行文件写到包外，已有路径不会被覆盖。无效输入、执行中重置、提前结束及失败均有记录。完整包含评价侧资料，策略只能接收公开观察；让模型读取整包会破坏评测条件。

## 采集过程与环境过程分别记录

原 v0.6 的外部采集器每条最多 12 次决策，但请求只显示环境 30 步，三条首次尝试均提前停止。这些原始请求与停止位置继续保留。

v0.7 从各自的 12 步状态续跑，每次请求显示真实剩余环境步数、整批剩余调用与时间，并公开字面检索、文档编号和终止动作。新增 11 次模型调用后，三条累计轨迹在第 17、17、13 步完成并通过原评分器。原来的评分与故障规则没有变化。

成功训练来源导出一条完整轨迹及五个新增恢复决策，两个测试家族仍排除训练。模型身份以请求配置记录。此次是已观察任务的修复验证，不能计成新的未见首次评测。采集中的保存失败、修复与不重复调用恢复也有单独记录。

## 从材料生成环境

冻结原始材料及来源摘要 → 确定任务发生时可见的信息 → 建立角色、权限、目标和初态 → 生成可观察工具与状态转移 → 建立可检验的末态要求 → 执行参考与负对照 → 保存真实尝试及筛选依据。

原始资料、事后解释、机器提取与合成补充使用不同标签。缺失内容继续标缺失；未来结果放在评价侧，不提前放进题面。适配器只能把有确定性依据的部分变成评分真值，其他事实维持未评定。

同源报告、修订和全部派生故障场景一起切分。当前训练与评测来源不重合，但共享模板；可迁移的候选能力是查证、权限与时间判断、有限重试、冲突恢复和证据不足时给出有限结论，其跨组织效果尚无充分证据。

旧 v0.4 另外保留七个 Python 排错任务及完整研究历史。其执行器运行可信候选程序，进程隔离不等于操作系统安全沙箱。环境结构、具体样本和适用边界见 [v0.7 数据说明](DATASET-v0.7.zh-CN.md)。
