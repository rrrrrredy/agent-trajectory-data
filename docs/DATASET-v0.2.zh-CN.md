# 研究执行与评审历史数据集 v0.2

这版把已有报告接回了实际研究运行：从任务提示、逐轮事件、可见动作，到产物快照、报告导出和后续评审，可以按同一研究家族查询。构建、离线验证和独立打包均已跑通。本版用于开发诊断。

新增数据由本地历史记录导入，新增模型调用为 0。原版 v0.1 完整保存在包内 base/，内容逐字节一致。两版共享同样的两组研究来源，不能相加当作四个独立研究家族。

## 直接使用

本地数据目录：data/research-history-v0.2。

    py -3 -B scripts/research_history.py verify data/research-history-v0.2
    py -3 -B scripts/research_history.py show data/research-history-v0.2 --run run-03

show 的 run-03 会显示视频研究的初稿、收到补充要求后暂停、续跑交付这三轮。原提示分别保存在 sources/runtime/run-03/turn-N.prompt.txt，产物与事件由 turns.jsonl、artifacts.jsonl 和 events.jsonl 对应。

从指定的既有材料重新构建一个新目录：

    py -3 -B scripts/research_history.py build --source D:\Codex\research-toolkit --runtime D:\Codex\industry-research-framework-field-eval\runs\calibration-20260907 --base data/research-slices-v0.1 --output data/research-history-rebuild

已冻结输出再次运行 build 时只验证原包，不悄悄刷新源文件。已有输出冲突会拒绝；源记录不会被修改，归档中的命令不会执行。

ZIP 解压后，可以脱离本仓库使用自带程序：

    py -3 -B verify_dataset.py verify .
    py -3 -B verify_dataset.py show . --run run-03

程序只使用 Python 标准库，不需要后台、数据库、网页或模型服务。

## 表之间怎样连接

| 文件 | 用途 |
|---|---|
| runs.jsonl | 运行、研究家族、条件与轮次 |
| turns.jsonl | 原提示、最终消息、前一轮、会话身份、用量和停止边界 |
| events.jsonl | 带源行号和原行摘要的可见事件 |
| actions.jsonl | 同一动作的开始与结束配对、输出可用性 |
| failures.jsonl | 原记录中明确的命令非零退出 |
| artifacts.jsonl | 文件内容、所属运行轮次、快照边界与原始哈希 |
| report_versions.jsonl | 报告的各个版本 |
| lineage.jsonl | 原运行到报告导出、稿件到评审、评审前稿到修后稿 |
| semantic_cases.jsonl | 合成案例原版、修订版和修订理由 |
| semantic_episodes.jsonl / semantic_events.jsonl | 评审调用及其请求响应引用 |
| judgments.jsonl / comparisons.jsonl | 模型判断、A/B 对应关系和批次间变化 |
| source_index.json | 原始来源、处理后的文件摘要、删减范围 |
| manifest.json | 文件清单、分开统计的两版数量与固定用途 |

同一原始研究、条件对照、续跑、报告版本和上版合成派生共享家族。所有数据固定在 development。作者标签和模型评审都保留各自来源，gold_label 为空，不用多数意见生成标准答案。

## 失败与决策怎样保留

记录可见动作及其上下文，不补写模型内部思考。两次显式暂停来自原提示“先停在这里”，随后由同一会话继续；没有改写成运行故障。

唯一命令非零退出来自对报告的 rg 文本扫描，exit code 为 1、输出为空。这种退出不能单凭数字判断研究失败，故只保留 command_nonzero_exit，任务质量为 not_assessed。

语义历史中，原作者后来修订了一个已被两个评审模型接受的对照片段：把“4 次通过标签检查”改为“至多 4 个标签合格候选”，避免直接等同于 4 个完全可用成片。原文、两模型原判断、作者修订理由与修订后评审都保留，原控制文本没有被覆盖。

另一案例澄清了报告正文与聊天进度消息的交付边界。重排批次也改变了上下文构成，因此保留前后判断变化，但不声明由位置偏差造成。

## 已核验的范围与缺口

- 291 个可见工具动作均有开始、结束配对；8 份最终消息与相应事件一致。
- 6 份逐轮快照清单的原文件哈希与采集边界已核对。没有原采集边界的末态目录另作标记。
- 8 份无关全局上下文输出已移除，原输出摘要保留；已知本地目录替换为占位符。隐藏推理不导入。
- 网页事件没有返回页正文；文件变更事件没有完整补丁。因此外部环境不可完整重放，不能声称恢复了全部研究过程。
- 本轮没有重新核验报告中的行业事实，也没有把进程结束、作者自评或模型判断当作报告通过。
- 后期稿件修订有版本与处置记录，但没有同等完整的作者执行轨迹。原评审结论不转移到修后稿。
- 训练记录和未见测试任务均为 0。当前用于开发诊断，闭源状态本身不改变来源材料的权利边界。
