# 数据集构建范围与完成标准

更新：2026-09-28。当前对象是独立闭源仓库中的 Agent 执行轨迹、评测数据和可执行环境。范围从数据设计开始就包括任务、操作轨迹、环境、评分标准、参考解法、失败与恢复证据。

## 已确认的边界

- 使用本地 research-toolkit 相关报告、冻结输入、评审和选定运行记录。
- 保留真实记录；合成任务、业务上下文、最小复现和脚本控制各自标明来源。
- 不增加访谈、员工补充、人工标注、人工复核队列。
- 不做商城、支付、网站、商业化或平台开发。此前偏离实现和相关技能已清理。
- 钉钉、飞书和员工解释只是来源举例；不要求接入这些平台。
- 先构建可执行数据，沿用现有调用预算，不以扩大模板数量替代数据质量。

## 已完成的构建

| 检查失败保留 | 无效输入、重试、未完成和原误判均可查；八类重算哈希的篡改被拒绝 |

## 自动流程

冻结选定来源 → 校验来源与用途 → 建立任务/版本/失败关系 → 标明已知缺失 → 生成可执行派生 → 运行对照 → 检查泄漏与重复 → 独立解包验证 → 私有版本发布。

无法自动判断的开放式质量保留 not_assessed。无法复原的历史环境保留 observation_replay_only。派生环境不替代原始记录，不用“修复后通过”覆盖第一次失败。

同源任务、重试、修订和合成派生留在同一切分。真实模型、脚本控制与外部客户端不混算。新样本只有实际执行后才拥有执行轨迹；可运行环境不等于已经训练出能力。

## 保留但退出主流程的旧内容

旧 300 条模板题、历史 5 条模型轨迹和早期部分会话保留在原数据目录；没有以它们扩增本次研究材料的独立任务数。旧服务、轮询、HTTP 接口不启动、不扩展。原月度 8 次模型调用预算已经用完，本轮不增加预算或换目录绕过。
