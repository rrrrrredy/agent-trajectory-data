# 下一阶段：验证已有轨迹是否有用

更新：2026-09-29。48 条用途实验已完成并全部重放通过，结果见 [实验结论](USEFULNESS-STUDY.zh-CN.md)。三条件均为 16/16 成功；完整轨迹的步骤优势几乎全部来自减少格式拒绝，尚未证明业务完成质量提升。本轮从继续扩充任务转向用途验证。四个模型同时进入正式实验，不设主备顺序；GLM 优先使用 Coding Plan，只有实际不可用时才考虑普通 API。用户已授权本次模型调用，不设金额上限。

目标：判断在证据变化、材料缺失和多文件修订中，已有示范能否改善完成质量或减少操作。沿用 research-workspace-1，不新建运行框架，不添加模型裁判。

四道题的来源实例和内容与两条示范分开，但共享任务作者、环境和工作流模板。这只是初步用途筛查，不是独立盲测、跨企业泛化证明或有统计把握的效果评估。四个模型的 token、推理设置与原生客户端并非同质，主要比较各模型内部 A/B/C 的变化。

若 A 全部通过，仍保留 B/C 结果观察操作开销，同时明确成功率没有区分度。C 更好才考虑一次小规模新来源复验；B 与 C 效果相当且更省输入，则优先整理短经验与案例；均无提升则停止沿当前方向机械扩容，先调整任务的实际用途和难度。

当前资产口径：v0.7–v0.16 共 37 个完成的逻辑任务执行，其中 3 个为原断点续跑；14 条成功执行可用于训练。最新统一消费包只包含其中 22 条执行、276 个步骤和 7 条成功训练示范。两个口径不能混用。新实验单独保存，不改写旧冻结版本；评测执行不自动进入训练集。

交付一份结果表和限制说明，附可重放的环境、示范、实际调用和最终产物，不新增复杂发布流程。
