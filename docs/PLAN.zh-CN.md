已落地的修复：有效动作不再因缺少理由被拒绝；解析错误有具体反馈；模型理由与采集器说明分开；模型回合与环境动作分别记录。N/E 对照中，一个 JSON 示例把总回合从 334 降至 312、理由缺失从 141 降至 9，但仍有 56 次格式拒绝。单样本成功差异不足以证明业务能力提升。

## 接下来按证据推进

1. **先做最小接口验证。** 四家均纳入，逐家核对当前支持的原生 JSON 或工具调用方式。沿用已验证的模型与通道，GLM 继续优先 Coding Plan。用公开合成输入检查一个动作能否稳定返回可解析结构、可见理由能否分开保存、真实错误能否完整保留；先解决已复现的工具标记混入文本问题，再决定是否需要另一批完整任务。文档支持不等于本配置已实测可用。
2. **保留具体失败，改进公开契约反馈。** LongCat 的失败不是数值算错，而是输出名称缺失。该案例同时含保护文字修正、重读检查恢复、最终评分失败。先区分公开可检查的结构要求与需要终态评分的内容正确性，再决定是否补充公开结构校验；不修改已冻结环境或事后把失败改判成功。
3. **出现新增用途才增加任务。** 现有四题已累计 80 次诊断执行，接口拒绝仍占较大部分。后续候选须增加现有任务没有的判断、修改或验证难点，并有可执行终态判据；不能只换数字、文件名或通过数量。当前不预排下一轮 32/48 条矩阵。

每一步交付具体缺陷、最小修复及实际证据。已有有效检查通过后，不为形成新版本重复全套测试。示例有效性按模型分别报告；不同时间、提示或接口的结果只作描述，不能混称单因素对照。
