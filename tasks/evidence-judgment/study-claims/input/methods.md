# 执行条件与计数说明

S1、S2：两轮都使用四个构造的工作区任务（cedar-pilot、linden-retention、harbor-backlog、wren-delivery），每个任务分别由 deepseek、glm、kimi、longcat 执行。用途轮每格一次、三个条件，共 48 条；格式轮每格一次、两个条件，共 32 条。任务包含给定材料、公式、判定规则、文件保护和环境预设故障。记录来自真实模型调用，输入不是企业生产日志。

用途轮 A 是基础说明，B 加短经验摘要，C 加完整示范。格式轮 N 修复接口但不放 JSON 示例，E 在同接口下加一个 JSON 示例。两轮之间更换了采集器、提示和调用时间。没有把两轮的底层服务版本、随机性与调用时间控制为相同。

旧采集器把格式拒绝记入 steps。`conditions.csv` 对齐为模型回合、格式拒绝、环境动作三个字段。`reward=1` 根据任务评分条件定义：既包括完成内容要求，也包括在必需材料缺失时正确停止。以格式轮 32 条为例，最终结果包括 23 条正确完成修订、8 条正确 blocked，以及 1 条最终内容失败。

格式轮有效动作中，N 有 141/266 条缺理由文字，E 为 9/256。记录不提供理由正确性的独立判定。金额成本未核算：没有统一输入输出单价、缓存计费、失败请求费用或人工耗时。输入 token 是各供应商上报量。

S3、S4：两份 `paired-*.json` 按同轮、同供应商、同任务配对，包含两边数值、右减左差值、交付状态、失败项和原结果文件哈希。它们是既有归档的离线重算。每份 16 对来自同四题，每格仍为一次执行。

本任务材料由作者从公开研究记录选取，条件表保留原数值，方法说明作压缩转述，配对 JSON 原样提供。来源版本和选择位置见 `sources.json`。许可见随包 `LICENSE`；公开访问不是另行授予使用、训练和再分发权利。
